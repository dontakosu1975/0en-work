# 0EN WORK 求職者向けPoC v0.2

トップ → 求人一覧・検索 → 求人詳細 → 企業指定の外部応募先、を検証する独立PoCです。frontend-designを使用し、紙色と深緑の検索中心の画面にしました。

## 起動

このディレクトリで `node server.cjs` を実行し、http://127.0.0.1:4177/ を開いてください。Node.js以外のインストールは不要です。`file://` では動きません。チェックは `node test.cjs`。

## 確認ポイント

1. トップから勤務地やキーワードで検索し、仕事の種類・雇用形態を絞る。
2. 一覧の2ページ目、詳細、検索結果への戻る、ブラウザの戻る・再読み込みを試す。条件はURLに残ります。
3. 給与の固定額・範囲・下限のみ、勤務時間、休日、試用条件を確認する。
4. 応募方法を見ると指定先の確認ダイアログが開く。架空求人の宛先はexample.com等のデモです。実際の応募はしないでください。
5. 同じ4177の「求人を掲載する」から企業ポータルを開き、求人管理で掲載停止・再掲載。求職者側の別タブへ反映されることを確認する。
6. 完成・未掲載の原稿、掲載終了原稿は検索に出ない。掲載中の原稿を編集中にしても、掲載時の完成版を表示する。

## データと分離

既存のJob/Revision/PublicationCycleと企業入力PoCのvalues/listsを再利用。求職者側は掲載中のCycleが参照する完成Revisionだけを投影し、別の求人スキーマを作っていません。元の会社ポータルと取り込みPoCをこのPoC内のcompanyへ複製し、localStorageで共有する接続のみ加えました。元の4174/4175のPoC、既存LP、設計文書は変更していません。

原稿はこのブラウザ・このオリジンのlocalStorage（キー `0en-seeker-poc-v02`）に保持します。端末間・別ブラウザ・別ポートの共有はありません。企業情報マスタ自体は従来どおりページ内状態です。フッターの初期化でこのPoCの原稿と掲載履歴をサンプルに戻せます。サンプルは架空10件、初期掲載8件、完成未掲載1件、掲載終了1件。応募先未設定のサンプルも含みます。実案件ファイルは同梱していません。

公開期限は閲覧時と5秒ごとの再評価で反映。実際の公開処理、法令チェック、認証、D1、応募者情報保存、AI、予約公開はありません。サンプルの「完成」は実際の法令適合を保証しません。

## 表示と参考実装

参考レビューで確認したURL検索条件・ページ切り替え・一覧比較・詳細表示の考え方を0EN向けに再実装。外部候補リポジトリのコードはコピーしていません。company内の既存XLSX読み取り用JSZipとLICENSEは元PoCから継承しています。

給与総額しかない場合に内訳を推定しません。内訳入力の場合は基本給＋一律手当＋固定残業代。上限は明示入力された総額だけを使います。確認済みの応募方法と受付先がある場合だけ外部リンクを作り、HTTP(S)以外のURLを拒否します。求人本文はHTMLとして実行せずテキスト表示します。

PoCはnoindexでJobPosting構造化データを出しません。SSR、正規URL、実際の404/410、実求人に一致したJSON-LDは本番化時の課題です。参考：[Google JobPosting仕様](https://developers.google.com/search/docs/appearance/structured-data/job-posting)。

## 検証

Nodeチェック：掲載期限・停止・未来の掲載・掲載時Revisionの固定、給与3表記と内訳総額、応募先必須と危険URL拒否。
ブラウザ：検索条件維持、ページ2、詳細直URL・再読み込み、応募先確認、未設定・終了求人のボタン非表示、企業ポータルからの停止・再掲載。1440/768/390pxの表示と390pxでの横はみ出しなしを確認。実応募は実行していません。

## UI共通化（2026-10-09）

色・OS標準フォント・入力欄・基本ボタン・ダイアログ・フォーカスは `assets/ui.css` に集約。全4画面（求職者、企業管理、取り込み、6ステップ入力）が同じ外部CSSを読み込みます。ページ固有CSSはレイアウト、条件分岐、個別の状態表示を担当。共通CSSを最後に読み込み、テーマの変更を各画面へ適用します。通常は `:root` の色・フォント・角丸から調整してください。Windows/macOSの画面を複製せず、馴染みのある標準文字・控えめな枠・青い選択状態を採用しました。

評価済みv0.1は変更なし。v0.2は独立したブラウザ保存キーのためv0.1の入力データを変更しません。認証やデータ構造の変更はありません。
