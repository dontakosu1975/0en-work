## 2. 論理構造と共通規約

| 論理単位 | 役割 |
|---|---|
| Job | 求人の識別、所有企業、現在の作業版・公開版の参照 |
| JobContentRevision | 募集主・原稿・雇用条件の版。通常編集／ステップ修正／CSV／運営編集が同じ項目を使う |
| PublicationCycle | 1回の掲載開始と終了。再掲載ごとに追加し、雇用契約期間と区別 |
| CheckRun / CheckIssue | 指定版に対するルール評価と修正先。内容変更後は以前の結果を公開判断に使わない |
| ChangeEvent | 誰が・いつ・どの値を変えたか。企業編集・運営編集・システムの掲載終了を区別 |

かんたん入力と詳細入力は同じJobContentRevisionを編集する。別スキーマや二重原稿は作らない。かんたん入力でも条件付き必須を省略できず、質問で入力する。詳細入力は補足項目を展開する。入力モードを求人属性として永続化する必要はない。

項目IDはドット区切りの論理パス。`[]` は配列要素。物理テーブル／API／CSV列名は未定。ID型は不透明な文字列で、UUID等の生成方式は要確認。金額は整数の円、時間量は整数の分、日時はタイムゾーン付きの瞬間（保存はUTC案、表示はJST）。期間は値＋単位で扱い、月を固定30日へ換算しない。enumは安定コードを保存し表示名と分離する。自由記述はプレーンテキスト案。

`null`＝未入力／不明、`false`＝明示的に「なし」、`0`＝明示的にゼロ。範囲上限のnullは、下限が入力済みなら「上限を表示しない」であり、無限の保証ではない。表示上の「応相談」は必須値の代替にしない。条件が非該当になった値は有効内容から除外し、古い値は履歴側だけに残す。

表の略記：公開「○」＝求人詳細に表示（構造から生成する表示を含む）、検索「K」＝キーワード、「F」＝絞り込み／並び順、「―」＝使わない。チェック「○」は必須・型・値・整合性等の対象、「―」は原稿チェック対象外。CSV「○」＝入出力、「出」＝出力のみ、「照」＝取込時の照合のみ、「―」＝除外。CSV対象は後続実装の設計でありPoCへの実装追加ではない。

比較用時間額は派生値。時給、日給÷平均日時間、月給÷平均月時間を要素別に求め、算入対象を合計する。固定残業代・通勤等の除外対象を含む表示総額をそのまま割らない。条件付き手当が保証されない場合、給与下限の比較に算入しない。年額・歩合・複雑な手当・特定最低賃金の対象判定が未対応なら、計算を止めて要確認とする。

給与検索は初期案では同じ給与単位の保証下限で比較する。月給・時給・収入例を混ぜて並べない。時間額換算値を検索に使うか、上限が希望額以上なら一致とするかは要確認。

## 12. CSV・複製・検索との対応

CSVは1行1求人案。JSON配列／オブジェクトをセルに格納する方式を候補とし、子項目を無制限に列展開しない。企業向けの読みやすさ、文字コード（UTF-8 BOM等）、見出し、改行・引用符、数式扱い防止、配列方式は要確認。今回CSV仕様書・パーサーは作成しない。

- 新規行はjob.id空欄。既存更新はjob.id＋revision.numberを照合する案。ID空欄行の再取込による重複生成をどう防ぐかは要確認。
- 更新は「全置換」か「差分更新」か要確認。本案は完全な1行を差分確認後に適用する方式を推奨。空セルを無視と解釈して消去不能にしない。null／false／0／空配列の表現を区別する。
- 所有権・型・条件付き必須・競合を検査し、行ごとの差分を表示する。CSV取込直後に公開しない。エラー行と正常行を部分適用できるかは要確認。
- 出力のみ／内部項目への入力は上書きしない。未知列、enumコード不一致、版不一致は黙って落とさず検出する。
- 複製は現在の選択した内容版をコピーし、新job.id・所有企業・版・作成日時を生成、下書きで開始する。掲載回・公開参照・チェック結果・過去履歴・停止解除権限はコピーしない。内容に含まれる古い日付・給与・勤務地は再確認／再チェックする。複製元を公開版／作業版のどちらにするかは要確認。
- 求人一覧・詳細は公開可能な掲載回と公開版だけを見る。原稿キーワード、都道府県／市区町村、職種、雇用形態、給与単位と保証下限を最小検索条件案とする。新着順は掲載回.started_at降順案。同時刻の安定順はjob.id等で補う。再掲載の新着扱いは要確認。

## 13. 決める必要がある事項

| ID | 要確認事項 | 決めない場合の影響 |
|---|---|---|
| Q01 | 応募・連絡方式、募集主公開連絡先の許容種別 | 公開必須条件と応募導線を確定できない |
| Q02 | 掲載できる雇用形態、派遣／業務委託、在宅・海外・複数勤務地 | 必須条件・最低賃金の適用地域が変わる |
| Q03 | 職種・勤務地・年齢例外・最低賃金のマスタ、更新担当・改定対応 | 検索・検査の意味を固定できない |
| Q04 | 年俸・歩合、手当の混在、複雑な固定残業制度のPoC受付 | 対応できない計算を要確認にする必要 |
| Q05 | 給与範囲と内訳の対応、保証給与の定義、検索一致の基準 | 表示総額・検索・賃金検査にずれが出る |
| Q06 | 変形・フレックス、特殊休日周期、試用期間の幅・延長 | 単純制度のルールを誤適用する恐れ |
| Q07 | warning／判定不能の公開可否、企業確認の証跡 | 公開ゲートを設計できない |
| Q08 | 公開中編集・運営編集の反映時点と企業確認、同時編集 | 未確認原稿の反映・上書きが起きる |
| Q09 | 28日の時刻計算、継続確認の通知時期、再公開・再掲載・新着の扱い | 期限・鮮度・停止の運用が揺れる |
| Q10 | CSV形式、空値、更新方式、重複、部分適用、配列の表現 | 誤更新・無断公開・情報欠落の恐れ |
| Q11 | 内部版・掲載回・履歴の保持期間、削除・閲覧権限 | 公開終了と内部削除を混同する |
| Q12 | 各stringの長さ上限、配列上限、ID・版の生成方式 | 保存・検査境界の具体化が必要 |

必須／条件付き必須の設計案についても、この表と対象範囲を決めたうえで次版へ確定する。未決定を空文字や推測した既定値で埋めない。

## 14. 設計の確認例（実装テストではない）

| 入力・操作例 | 本スキーマでの扱い |
|---|---|
| 時給・固定残業代なし・試用なし・無期・固定時間 | 不要な残業代／試用／有期子項目を要求しない |
| 月給25万円・固定残業代3万円・対象20時間 | 25万円を基本給と誤認しない。基本給／手当／残業代／平均時間を別に検査 |
| 試用期間中のみ月給20万円 | 同型給与構造の差分を持ち、試用条件でも最低賃金評価 |
| 日給＋月額の職務手当 | それぞれの支給単位と平均日／月時間で比較。根拠不明なら要確認 |
| 22:00～翌7:00・休憩60分 | 翌日フラグで拘束9時間、所定8時間を算出。深夜と年齢条件は別検査 |
| 有期3か月・条件付き更新・上限3回 | 期間・更新基準・回数を構造で保持。求人の28日掲載とは独立 |
| かんたん修正で固定残業代ありへ変更 | 子項目不足を検出し、通常編集と同じパスを更新・履歴記録 |
| 公開済み求人を企業／運営が編集 | 誰・いつ・差分を保存し、旧公開版と新作業版を区別 |
| 28日経過・再掲載・原稿複製 | 期限終了／新掲載回／新Jobを別操作として扱う |
| CSVが他社job.idや公開日時を指定 | 所有権・保護項目を検査。入力した値で公開しない |
