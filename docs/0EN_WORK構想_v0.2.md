# 0EN WORK 構想 v0.2

作成日：2026-10-18

## 1. この文書について

0EN WORKは、当初「求人掲載 0円・応募 0円・採用 0円」を軸にした求人サービスとして検討を始めた。

その考え方と求人機能は残しつつ、0EN WORK全体の立ち位置を、求人だけに限定しない形へ広げる。

本書はその新しい上位構想を整理するものであり、既存の求人関連仕様を廃止するものではない。求人システム、求人原稿作成補助、企業向け機能などは、0EN WORKに存在する一つの「WORK」として継続する。

## 2. 0ENにおける「WORK」

0ENにおけるWORKは、「仕事」だけを意味しない。

誰かが何かに取り組んでいること、その取り組みから生まれたもの、そこで役立ったもの、誰かに紹介したいものを広くWORKとして扱う。

例：

- アプリ開発
- Webサイト・Webサービス
- ゲーム開発
- 編み物
- 裁縫
- 木工
- 金工
- 3Dプリンタ
- 電子工作
- 音楽制作
- 求人広告・採用活動
- 原稿作成を助けるツールやサービス
- その他、誰かの取り組みに関係するもの

ジャンルは最初から固定しない。利用や紹介が増えれば、新しいジャンルを追加できる構造を目指す。

## 3. 0ENの役割

0ENは、すべてのWORKを自分で提供・保管・配布する中央集権的なプラットフォームを目指さない。

0ENの主な役割は、WORKを「見つける」「紹介する」「つなぐ」ためのHubになることである。

利用者は0ENの紹介ページを入口として、作者・運営者等のホームページ、GitHub、X、Threads、ブログ、動画サイト、配布ページ、ストアなどへ移動できる。

0EN内に利用者を囲い込まず、外部へ出ていくリンクを重要な機能として扱う。

## 4. 発想の原点

インターネット黎明期には、個人がHTMLでホームページを作り、便利なソフトや情報を友人へ渡し、使った人が自分のホームページで紹介し、相互リンクによって人・サイト・情報のネットワークが広がっていった。

0ENは、その時代の見た目や技術を再現することを目的としない。

現代では失われつつある「誰かが見つけた便利なものを紹介し、リンクをたどって別の誰かや別の取り組みに出会う」という仕組みを、現在のWeb、SNS、GitHub、AI等と組み合わせて再構成する。

## 5. 「紹介」を中心にする

0ENでは、SNSのような日々の「投稿」や「発信」よりも、「紹介」を中心語として扱う。

例：

- 自分のWORKを紹介する
- 自分が作ったアプリを紹介する
- 便利だったWORKを紹介する
- 参考になったサイトを紹介する
- 関連するWORKを紹介する
- 作者や活動先を紹介する

紹介は本人によるものに限定しない。第三者や0EN運営が紹介することも想定する。

ただし、本人による紹介、第三者による紹介、0EN運営による紹介など、情報の出所を利用者が判別できるようにする。

## 6. アプリ・ソフトウェアの紹介

AIによって個人が小さなアプリを作るハードルは下がっている。一方、完成後に「どこで公開するか」「どうやって知ってもらうか」は依然として難しい。

GitHubは有力な公開・配布場所だが、開発経験のない利用者にとっては、Release、Assets、ソースコード等の違いが分かりにくい場合がある。

0ENはGitHub等の代わりにファイルを保管することを主目的とせず、一般利用者と配布元をつなぐ入口になる。

例：

- Windows版をダウンロード → GitHub Releases
- Android版を入手 → Google Playや作者指定ページ
- ソースコードを見る → GitHub
- 作者を知る → 作者ホームページ
- 制作状況を見る → X / Threads / ブログ等

0EN上では、技術的な配布先を分かりやすい言葉で案内する。

0ENが紹介したアプリ・サービス・ファイルについて、安全性、完全性、継続提供、特定環境での動作等を保証するものではないことを明示する。公開時には、通報、削除、危険な配布物への対応方針も別途整備する。

## 7. 相互リンクを主要機能として扱う

相互リンクは0ENの宣伝施策ではなく、0EN WORKのネットワークを成立させる主要機能とする。

0ENから作者サイト等へリンクするだけでは、0ENは単なるリンク集になる。

作者・運営者側からも0ENの紹介ページや関連WORKへリンクできることで、Web上に双方向の経路を作る。

リンクには少なくとも次の状態を想定する。

- 0ENから外部への片方向リンク
- 外部から0ENへのリンク
- 双方がリンクしている相互リンク
- WORKから別のWORKへの紹介リンク

相互リンクの方法は、技術に詳しくない人でも利用できるようにする。

例：

- 通常URL
- HTMLリンクコード
- GitHub README向けMarkdown
- 0EN Builderからの簡単なリンク追加
- SNSで共有しやすいURL

「相互リンク済み」は、0ENが一方的に情報を収集しただけではなく、外部側にも0ENへの経路が存在することを示す情報として扱える。

## 8. WORK同士のネットワーク

ジャンル分類だけでなく、WORK同士のリンクを重視する。

例えば、木工のWORKから3Dプリンタで作る治具へ、3DプリンタからCADツールへ、ゲーム開発から音楽制作へ、といったジャンルを越えたつながりを許容する。

カテゴリは「入口」、タグは「関係するテーマ」、リンクは「人が実際につないだ関係」として、それぞれ別に扱う。

利用者が一つのWORKを見つけ、関連WORKをたどり、思いがけない別の取り組みに出会える状態を目指す。

## 9. 外部SNS・コミュニケーションとの関係

0EN自身が大規模なSNSやコミュニケーション基盤を持つことを前提としない。

作者・利用者は、それぞれが使いやすい場所で交流できるようにする。

例：

- X
- Threads
- GitHub
- Discord
- YouTube
- ブログ
- 個人ホームページ
- その他の外部サービス

0ENの紹介ページから、それらの活動場所へたどれるようにする。

同時に、外部SNSや作者サイトから0ENの紹介ページへ戻れる導線を用意し、0ENと外部サービスの間を行き来できる構造を目指す。

## 10. 作者・紹介者が能動的に参加できること

0EN運営がWeb上から情報を集めるだけでは、単なる編集型リンク集になってしまう。

WORKを行っている本人や、それを便利だと思った人が、自分から紹介できる仕組みを用意する。

想定する行動：

1. 自分のWORKを紹介する
2. 作ったもの・公開したものを紹介する
3. 作者HP、GitHub、SNS、配布先等を登録する
4. 関連するWORKを紹介する
5. 自分のWORKから別のWORKへリンクする
6. 相手側からもリンクされた場合、相互リンクとしてつながる
7. その紹介ページを外部SNS等で共有する

「作者」という呼称はアプリ等では分かりやすいが、求人、手芸、研究、活動等すべてに適するとは限らないため、正式な呼称は今後検討する。

## 11. AIの役割

AIは0ENの主役ではなく、ネットワークを維持・拡張する裏方として利用する。

想定する用途：

- 各ジャンルのWORK候補の調査
- 個人サイト、ブログ、GitHub、SNS等の調査
- 相互リンク候補の発見
- ジャンルやタグ候補の整理
- 紹介文の下書き
- 相互リンク依頼文の下書き
- リンク切れの確認
- 関連しそうなWORK同士の候補提示

AIによる自動的な大量営業や無断連絡を目的としない。外部への連絡や掲載判断については、運用ルールを設ける。

## 12. 求人機能の位置付け

求人広告・採用は0EN WORKの中心から排除するものではない。

求人広告もまた、0EN運営者自身が行っている一つのWORKとして位置付ける。

そのため、既存の以下の機能・構想は継続できる。

- 求人検索・求人詳細
- 無料求人掲載
- 求人原稿作成補助
- 求人管理
- Airワーク等からの取り込み
- SNS・LINE・QR等への共有
- 企業サイトや応募先への外部リンク

求人分野は、0EN WORKの中で比較的大きく育った一つのジャンルとして扱う。

## 13. 0ENが目指す状態

0ENは「何の専門サイトか」を一つのジャンルで説明できなくてもよい。

編み物、裁縫、木工、金工、3Dプリンタ、ゲーム開発、アプリ、Web、求人などが同居できる。

共通するのは、そこに誰かのWORKがあり、そのWORKを誰かに紹介でき、作者・配布先・SNS・別のWORKへつながれることである。

0ENは、誰かのWORKと、誰かや何か、そして外部のWebやSNSをつなぐHubを目指す。

## 14. 現時点での設計原則

1. WORKを「仕事」に限定しない。
2. ジャンルを固定しすぎず、後から広げられるようにする。
3. 「投稿」より「紹介」を中心にする。
4. 0EN内にコンテンツや利用者を囲い込まない。
5. 作者HP、GitHub、SNS、配布先等への外部リンクを重要視する。
6. 相互リンクを主要機能として設計する。
7. WORK同士のジャンル横断リンクを許容する。
8. 作者・紹介者自身が能動的に参加できるようにする。
9. 0EN運営・AIによる調査と、利用者自身による紹介の両方を成立させる。
10. 0ENが保証していない外部アプリ・サービスについて、その立場を明確に表示する。
11. 求人機能は廃止せず、0EN WORK内の一つのWORK／ジャンルとして継続する。
12. 外部SNS等を置き換えず、それらへつながり、それらから戻れるHubになる。

## 15. 今後の検討事項

- WORK紹介ページの共通スキーマ
- 本人紹介／第三者紹介／0EN紹介の表示方法
- 作者・活動者等の正式な呼称
- カテゴリとタグの管理方法
- WORK間リンクのデータモデル
- 相互リンク確認方法
- 外部サイト向けリンクコード／バッジ
- GitHub Releases等への初心者向けダウンロード導線
- 投稿・紹介時の審査とモデレーション
- 通報・削除・危険サイト／危険ファイルへの対応
- 著作権・商標・なりすましへの対応
- リンク切れの検出と表示
- 外部SNS共有機能
- 求人以外のWORKを含めた利用規約・公開ポリシーの改訂
- 既存LPを新構想へどう移行するか

本書は構想段階の上位方針であり、実装仕様、正式な利用規約、法的な保証内容を定めるものではない。
