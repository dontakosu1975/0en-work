# 専門LP・WORK導線構想（仮案 v0.1）

作成日: 2026-10-18

## 目的

0EN Hubのトップページへ機能や説明を集中させず、利用目的が明確な領域については専門LPを入口として追加する。

Hubを巨大なポータルへ育てるのではなく、WORKの蓄積や利用者ニーズに応じて必要な入口を後から増やす。

## 基本構造

- **0EN Hub**：さまざまなWORKを検索・発見する総合入口
- **専門LP**：特定の目的を持つ人向けの入口
- **WORK一覧**：検索・カテゴリ・専門LPなどから到達する比較・探索画面
- **WORK詳細**：共通掲載フォーマットを使い、内容を理解して外部サイトや次のWORKへ進む場所

専門LPは独立したデータ群を持つ別サービスに限定しない。原則として、0EN Hubに登録された共通のWORK群を目的別の切り口で見せる。

## 求人領域の例

### 求職者

0EN Hub
→ 「働く」または検索
→ 求人WORK一覧
→ 求人WORK詳細
→ 応募先・企業サイト

### 求人企業

0EN求人LP
→ 求人掲載の説明
→ 企業登録・求人作成
→ 求人WORKとして公開
→ 0EN Hub / 「働く」 / 検索結果にも掲載

企業向けには「WORK」という概念を前面に出しすぎず、「求人を無料で掲載する」など目的に合った言葉を使用する。内部では求人を `WorkType = job` として共通WORKの一種として扱う。

## 企業向けLPから他のWORKへつなぐ

0EN求人LPや求人作成後の画面では、採用活動や企業活動に役立つWORKを紹介できる。

例：

- 0EN Builder：採用ページ・会社紹介ページの作成
- 求人画像作成に役立つWORK
- QRコード作成WORK
- SNS告知支援WORK
- 採用文章・写真撮影などのノウハウWORK
- 外部作者が公開する企業向け便利ツール

0EN自身が提供するWORKだけに限定しない。他の作者・事業者のWORKも、関係が明確であれば同じ仕組みでつなげる。

## 専門LPの増殖モデル

最初から多数の専門サイトを設計しない。

1. WORKが増える
2. 特定領域のまとまりが見えてくる
3. 必要なら小分類を作る
4. さらに需要や掲載数が増え、専用入口が有効になった段階で専門LPを作る
5. 専門LPから既存の共通WORK群へ誘導する

将来例：

- 0EN求人
- ものづくり系の専門入口
- Web・アプリ制作系の専門入口
- その他、実際のWORK蓄積から必要性が生まれた領域

専門LPは固定的なサイト体系ではなく、需要に応じて後から追加・統合・終了できる入口として扱う。

## 0EN Builderとの関係

将来的には専門LP自体を0EN Builderで制作・管理する構成も検討できる。

つまり、0EN上でWORKが増え、そのWORKを見つけやすくする新しい入口を0EN Builderで作る、という循環を作れる。

ただし初期実装ではBuilder連携を必須条件にしない。

## トップページ案との役割分担

2026-10-18時点のトップページ3案では、次の使い分けが有力。

- **案1「検索ファースト」**：0EN Hubトップの骨格候補
- **案2「コンパクトな索引」**：検索結果・カテゴリ一覧など、複数WORKを比較する画面の参考
- **案3「やさしい案内所」**：キーワードが分からない人向けのカテゴリ導線として一部を案1へ取り込む候補

トップページには専門領域の説明を詰め込まず、検索・カテゴリ・WORK紹介入口を優先する。

## 設計原則

> Hubは何でも探せる総入口。専門LPは目的別の入口。中身は共通のWORKでつながる。

- Hubトップを機能の寄せ集めにしない
- 専門LPを増やしてもWORKデータを不必要に分断しない
- 求人だけを特別な別世界にしない
- 利用者には、その入口の目的に合った言葉を使う
- 専門LPから関連する他者のWORKへも自然につなぐ
- 新しい専門LPは実際のWORK蓄積と需要を見て追加する
