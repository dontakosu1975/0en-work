# 企業登録画面 仕様案 v0.1

作成日：2026-10-09  
対象：0EN WORK の企業向けフロント  
状態：実装前の検討案。認証、DB、メール送信、公開設定は変更しない。

## 1. 目的

公開LPの「0ENを無料で使う」から、企業担当者が迷わず求人作成へ進める入口を定める。

登録画面は、将来の認証・企業アカウント・メンバー権限を想定したUIにする。ただし、この段階ではブラウザ内の一時状態で登録体験だけを確認する。

導線は次の1本にする。

```text
公開LP
  ↓ 0ENを無料で使う
企業登録
  ↓ 登録内容を確認
企業ホーム
  ↓ 求人を作る
求人入力
```

登録前に説明ページを何枚も挟まない。利用条件への同意は登録画面内で扱い、詳しい方針・プライバシー・利用規約は画面下部から確認できるようにする。

## 2. 用語と関係

画面上では専門的な内部名を出さないが、将来のデータ境界は次のように分ける。

| 概念 | 意味 | 求人との関係 |
|---|---|---|
| 企業 | 求人を所有し、掲載主体となる会社・事業者 | `Job`を所有する |
| 担当者 | 企業の管理画面を使う個人 | 企業に所属する |
| 所属 | 担当者と企業の関係、将来の権限を持つ | 企業ごとに役割を持つ |
| 求人原稿 | 企業が作成・保存する原稿 | 企業に属する |
| 原稿の版 | 編集中と公開済みを分ける履歴 | 求人に属する |
| 掲載回 | いつ、どの版を公開したか | 求人と版を参照する |

最初に登録した担当者は将来の`owner`相当とする案が自然だが、画面では「管理者」などの権限用語をまだ表示しない。メンバー招待や権限変更は別画面で後から追加する。

## 3. 登録画面の項目

### 必須

- 会社名・事業者名
- 登録担当者名
- 登録用メールアドレス
- 利用規約・プライバシーポリシーを確認したこと

### 任意

- 会社の所在地
- 会社のWebサイト
- 企業の公開連絡先
- 電話番号

会社名・事業者名は法人に限定しない。個人事業主や店舗単位の事業者も登録できる。ただし、雇用主となる事業者名と、実際に働く店舗・拠点の名前は混ぜず、店舗・勤務地は求人側で管理する。

登録用メールアドレスと企業の公開連絡先は分ける。登録用メールアドレスを、求職者向けの応募先や公開連絡先へ自動反映しない。

応募方法・応募先は企業情報ではなく求人ごとに設定する。選択肢は外部フォーム、メール、電話、企業採用ページなどとし、企業情報に登録した公開連絡先は求人作成時の候補として選べるだけにする。未設定の応募先を自動公開しない。

### 今回は聞かない

- 法人番号
- 業種の詳細分類
- 従業員数、売上規模
- 採用予定人数
- パスワード
- メンバー一覧
- 支払い情報

求人作成に必要な会社情報は、登録完了後の「企業情報」画面で追加・編集できるようにする。

## 4. 画面構成

### 4.1 登録画面

見出し：`0ENを無料で使う`  
説明：`会社の情報を登録して、求人ページを作成します。`

1. 会社名・事業者名
2. 登録担当者名
3. 登録用メールアドレス
4. 企業所在地や公開連絡先は、求人公開前に追加・確認できる説明
5. 利用規約・プライバシーポリシーへのリンク
6. 同意チェック
7. `登録内容を確認する`ボタン

内部スキーマ名、Company ID、User ID、Membershipなどは画面に出さない。

### 4.2 登録内容の確認

入力値を一覧表示し、次の操作だけを提供する。

- `修正する`
- `この内容で登録する`

このPoCではメール送信や認証を行わず、登録完了をブラウザ内の状態として扱う。

### 4.3 登録完了

表示例：

> 企業情報を登録しました。求人ページを作成できます。

操作：

- `求人を作る`
- `企業情報を確認する`

既存の企業ポータルへ遷移し、会社名・事業者名、所在地などを新規求人の初期値へ反映する。求人の勤務地は企業所在地とは別に、求人ごとに設定する。

## 5. 将来の認証を考慮したUI

今回のPoCでは認証を実装しないが、画面上の役割は次のように分ける。

- 登録用メールアドレス：ログイン・本人確認に使う非公開情報
- 企業の公開連絡先：必要に応じて求人作成時の候補になる情報
- 求人の応募方法・応募先：求人ごとに明示し、公開前に確認する情報
- 会社のWebサイト：求人詳細に表示する公開情報
- 担当者名：企業管理画面で表示する情報。公開するかは求人ごとに判断する

将来の認証方式は、パスワードを持たないログイン用リンク方式を候補とする。実装時には、リンクの有効期限、1回限りの使用、再送制限、アカウント存在の推測防止、ログアウト、メール変更を別途定める。

## 6. セキュリティ基本方針との整合

- 登録画面から応募者情報を取得しない。
- 登録用メールアドレスを公開求人へ自動表示しない。
- 企業所在地と求人の勤務地を同じ情報として扱わない。
- 求人ごとの応募方法・応募先を、企業情報の登録だけで確定しない。
- クライアントから送られた企業IDを所有権の根拠にしない。将来は認証済みセッションから企業を確定する。
- 登録、確認、ログイン用リンク送信にはレート制限とBOT対策を入れる。
- 企業名、URL、問い合わせ先を表示するときはHTMLとして実行せず、値をエスケープする。
- 会社のWebサイトは`http`または`https`だけを許可し、ユーザー名・パスワードを含むURLは受け付けない。
- 同意した規約の版、同意日時、対象企業、担当者を将来記録できるようにする。
- 企業の存在を推測できる登録・ログインエラーを返さない。

## 7. 既存PoCとの対応

現在の企業情報PoCには、次の項目がある。

| 現在の項目 | 登録画面での扱い | 備考 |
|---|---|---|
| `name` | 会社名・事業者名 | 必須 |
| `address` | 企業所在地 | 任意。求人初期値の候補。公開前に確認 |
| `website` | 会社のWebサイト | 任意。安全なURLだけ表示 |
| `person` | 登録担当者名 | 必須 |
| `email` | 登録用メールアドレス | 非公開。求人の公開連絡先とは分離する |
| `phone` | 企業の公開連絡先候補 | 任意。求人ごとに公開可否を確認 |

既存PoCの`email`を求人問い合わせ先へ自動反映している部分は、登録用メールと公開連絡先を分離するために見直す。求人入力の`contact`は、企業情報ではなく求人側の応募方法・応募先として扱う。企業の公開連絡先をメールで登録する場合の独立項目は、後続の企業情報画面で追加する。

## 8. 公開前に確認する情報

登録は簡単に完了できるが、求人を公開する前に次を確認する。

- 雇用主となる会社名・事業者名
- 企業所在地
- 求人ごとの勤務地
- 求人ごとの応募方法・応募先
- 公開する企業Webサイト・公開連絡先の有無

企業所在地は登録時に空欄でもよい。公開操作では未確認として残し、入力または確認が済むまで公開できない状態にする。

## 9. 残る未決事項

以下は登録画面の実装前、または認証・DB設計時に決める。

1. 登録用メールアドレスのドメイン確認を、どの認証方式で行うか。
2. 1人の担当者が複数企業を管理できるか。
3. 企業の削除・休止・担当者変更の手順。
4. 規約改定時の再同意と、同意履歴の保存期間。
5. 求人ごとの応募方法・応募先で許可するURL・メール・電話の検証ルール。

## 10. PoC実装の受入条件

実装時は次を確認する。

- LPから登録画面へ1クリックで進める。
- 登録用メールアドレスが公開求人へ勝手に表示されない。
- 会社名・事業者名と勤務先店舗・勤務地を別々に入力・確認できる。
- 企業所在地が空欄でも登録でき、公開前には確認を求められる。
- 応募方法・応募先を求人ごとに設定でき、未設定のまま公開できない。
- 登録内容の確認・修正・完了・求人作成の遷移が成立する。
- 登録済み会社名・所在地が新規求人の初期値へ反映される。
- 再読み込みで消えるブラウザ内PoCであることが画面に明記される。
- 認証やメール送信を実装したように誤認させる表示をしない。
- 企業情報と求人情報の入力欄に、内部スキーマ名を表示しない。

この仕様案が確定するまでは、登録画面の実装、認証、DB接続を開始しない。
