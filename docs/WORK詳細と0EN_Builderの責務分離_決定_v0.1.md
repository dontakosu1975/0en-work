# WORK詳細と0EN Builderの責務分離（決定 v0.1）

更新: 2026-10-18

## 結論

**0ENのWORK詳細ページと0EN Builderは別物として扱う。**

0EN BuilderはLP・Webページを作成する独立したWORK／ツールであり、0ENのWORK詳細ページを生成・編集するためのエンジンではない。

WORK詳細ページでは、利用者によるHTML自作・任意コード埋め込みを許可しない。

---

## 1. WORK詳細ページ

WORK詳細は0EN側が管理する固定テンプレートで表示する。

利用者が登録するのは「ページのHTML」ではなく「WORKの情報」。

例:

- WORK名
- 短い説明
- 詳細説明
- 画像
- カテゴリ
- 状態
- 提供者・紹介者
- 公式URL等の外部リンク
- 関連WORK
- 種類別の構造化項目

0ENはDBに保存された情報を安全な固定テンプレートへ流し込み、WORK詳細ページを生成する。

### 許可しないもの

初期仕様では少なくとも以下を許可しない。

- 任意HTML
- 任意JavaScript
- scriptタグ
- iframe等の自由埋め込み
- 任意CSSによるページ全体の変更
- ユーザー作成コードの直接実行

これにより、XSS、偽ログイン画面、偽ダウンロード導線、外部スクリプト、意図しないトラッキング、レイアウト破壊等のリスクを抑える。

基本原則:

> **ユーザーは「情報」を登録する。0ENが「ページ」を作る。**

---

## 2. 0EN Builder

0EN BuilderはLP・Webページを作成するための独立したツール。

用途例:

- 企業LP
- 採用LP
- 商品・サービス紹介LP
- 個人ページ
- 活動紹介ページ
- その他のWebページ

0EN Builder自体も0EN上では一つのWORKとして紹介できる。

つまり、

```text
0EN Builder
   ├ 独立したLP作成ツール
   └ 0EN上では「紹介されるWORK」の一つ
```

であり、

```text
0EN Builder
   └ WORK詳細ページ生成エンジン
```

ではない。

---

## 3. WORK詳細とBuilderの接点

必要に応じてWORK詳細からBuilderで作成したLPへ外部リンクできる。

例:

```text
求人WORK
 ├ 応募する
 ├ 企業サイト
 └ この会社について詳しく見る
          ↓
     Builder製の採用LP
```

逆にBuilder製LPから0ENのWORK詳細へリンクしてもよい。

この接続は「同じページシステムだから」ではなく、0ENが重視する外部Webとのリンク・相互リンクの一例として扱う。

---

## 4. 求人WORK

求人もWORK詳細の固定テンプレートで表示する。

求人入力画面から、例えば以下の構造化情報をDBへ保存する。

- 会社・事業者
- 職種
- 仕事内容
- 給与
- 勤務地
- 雇用形態
- 勤務時間
- 休日
- 応募先
- 掲載期間

これを0EN側の求人WORK表示へ流す。

求人企業がより自由な採用ページを必要とする場合は、0EN Builder等で別途LPを作成し、求人WORKからリンクする。

したがって、求人WORKの安全な固定表示と、Builderによる自由度の高いLP作成は混同しない。

---

## 5. DB・レンダリングの責務

```text
             WORK DB
                │
       ┌────────┴────────┐
       ↓                 ↓
 software WORK         job WORK
       │                 │
       └──────┬──────────┘
              ↓
       0EN固定レンダラー
              ↓
         WORK詳細HTML
              ↓
      SEO / JSON-LD / OGP
```

0EN Builderはこのレンダリング経路の外にある。

```text
0EN Builder
     ↓
独立したLP / Webページ
     ↕ リンク
0ENのWORK詳細
```

---

## 6. SEO・AI検索との関係

WORK詳細を0EN側の固定テンプレートで管理することで、全WORKについて以下を統一しやすくなる。

- title
- meta description
- canonical
- OGP
- 見出し構造
- パンくず
- JSON-LD / Schema.org
- 更新日時
- 関連WORKリンク
- 主要本文のクロール可能性

ユーザーが自由HTMLを作る方式より、検索エンジン・AI検索に対して一貫した構造を提供できる。

---

## 7. 初期実装への反映

初期実装は次の順を基本とする。

1. WORK共通スキーマ v0.1を確定
2. DB設計
3. 0EN固定WORK詳細テンプレートを作成
4. 0EN Builderを最初のWORK候補としてDBへ登録
5. 0EN求人をWORKとして登録
6. Builder → 0EN求人等の関連付けを試す
7. SEO / JSON-LD / OGP等を確認

ここで0EN BuilderをWORK詳細の生成に使用しない。

---

## 設計原則

> **WORK詳細は安全で統一された0ENのページ。Builderは自由度の高いLPを作る別のWORK。両者はリンクでつながる。**
