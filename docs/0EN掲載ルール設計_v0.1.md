## 1. 方針と読み方

企業が説明なしでも求人を作れるセルフ掲載を基本とする。掲載・応募・採用・複製・再掲載は無料、順位は売らない。通常求人の原稿を運営が毎回事前承認する仕組みにはしない。一方、求人者の実在確認と、危険な求人を掲載前に確認・保留する仕組みは必要。無料であることや28日で終了することは、不正募集対策の代わりにならない。

青本はルールを発見する資料として使い、現在の法令・公的指針・求職者と第三者への害・0ENの目的から選別する。「他媒体で禁止」「青本の×例」だけでは禁止理由にしない。合法な募集と0ENで受け付ける募集は別問題であり、PoCの対象外を違法求人と呼ばない。

成果物は本書と[青本ルール棚卸し_v0.1.md](青本ルール棚卸し_v0.1.md)の2ファイル。棚卸しの各行に、元ルール・分類・概要・扱い・理由・4つの由来・自動判定・スキーマ項目・修正質問・要確認を収録した。複数の意味がある元ルールは枝分けした判断を併記している。本書はその共通判断の説明、禁止語候補、独自候補、公開ゲートを整理する。

## 3. 分類と公開ゲート

| 分類 | 意味 | 公開の扱い案 |
|---|---|---|
| block | 犯罪募集、確認済みの権利侵害、利用停止回避など、掲載対象そのものを拒否する | 公開不可。表面の単語削除だけで解除せず、原因・主体・業務を再確認 |
| error | 必須不足、数値矛盾、誤った条件表示など、求人の訂正で解消できる | 対象版を修正し再評価するまで公開不可 |
| warning | 文脈次第で問題になり得るが、検出だけでは掲載不可としない | 他の阻止要因がなければ公開可能案。警告表示と具体的な確認を促す |
| unable_to_evaluate | 適用条件・裏付け・判断機能が不足する | **安全・権利・本人確認の重大な疑義は保留**。計算未対応等の通常不明と区別し、代替確認後の可否を決める |
| allow | 元媒体の制限を0ENでは採用しない、又は適法で明確な表記 | そのルールを理由に阻止しない。他のルールの評価は継続 |

法令由来だから全てblock、自由文だから全てwarning、とはしない。例えば最低賃金未満の条件はerrorで条件訂正を求める。犯罪の実行者募集や、故意の虚偽条件を繰り返す主体はblockと利用停止の候補。法令例外の判断資料が足りないときはunable_to_evaluate。

`unable_to_evaluate`は一律許可でも一律運営承認でもない。保留理由、必要資料、担当、解除条件を明示し、回答後に同じ版を再評価する。重大疑義を「企業が問題なしにチェックした」だけで解除しない。回答不能・不審点が残る場合は保留を継続する。通常の未対応制度について公開を認める代替確認の範囲は**要確認**。

同じ原稿で複数問題があれば最も厳しい未解消条件が公開ゲートを決める。warningへの同意によってerror・blockを上書きできない。既存公開版に重大な危険が見つかれば、新作業版だけ保留して既存版を公開し続けない。停止と証拠保全を検討する。[L02](https://www.mhlw.go.jp/content/001423401.pdf)

## 4. スキーマとの接続と入力を簡単にする判断

### 求人原稿の母艦としての再利用

0ENで作った原稿を0ENに囲い込まない。企業が自作した原稿と、有料制作の完成原稿は、企業が編集・複製・再利用できる思想を採用する。0ENの無料掲載、自社採用HP、Airワーク、他媒体へ利用することを妨げる媒体都合の制限を設けない。第三者制作物の権利まで企業が持つと推定せず、制作サービスの利用権・第三者素材の許諾範囲は規約設計で要確認。掲載権を販売する仕組みにしない。

将来の「原稿をコピー」は構造データから仕事内容→給与→勤務時間→休日・休暇→待遇→試用期間→応募条件等へ整形する候補。給与は給与形態・基本給・保証される一律手当・固定残業代から総額を生成し、条件付き手当や変動例を混入させない。企業に総額やチェック用換算値を重複入力させない。

**次版の設計確認条件に「Airワークの主要入力項目へ無理なく変換できるか」を追加する提案**とする。意味・金額・単位・保証条件・試用時差分が失われないことを確認する。Airワークの現行入力欄との詳細照合は今回行っておらず、変換可能性の検証は要確認。完成画面・コピー機能・変換器は実装しない。元スキーマも今回は変更しない。

0ENのチェックを通ったことはAirワーク・Indeed等の審査通過を保証しない。「共通の法令・安全・権利確認」と「掲載先固有の互換性チェック」を将来別に扱い、0ENではallowにした媒体制限をコピー先の警告として追加できる設計を検討する。0EN掲載の可否を他媒体の都合で決めない。

スキーマv0.1の `check.issues[].level` はerror/warning/unable_to_evaluate案で、blockとallowがない。本書の分類を既存enumに黙って押し込まない。blockを掲載資格判定側に分けるかenumを拡張するかは次版で要確認。allowは通常、問題レコードを生成しない。今回はスキーマを変更しない。

本書・棚卸しで用いる `salary.*` 等の表記は既存項目の集合を指す便宜的な参照で、実在する新項目ではない。各判定時には具体的な `field_paths` に展開する。画像、企業実在確認結果、許認可情報、権利許諾証拠など、現在ないデータは「未収録」と記す。原稿自由文へ内部審査データを詰め込まない。

| 対象 | 既存情報から行うこと | 企業への質問が必要なこと |
|---|---|---|
| 基本明示 | `employer.*`、`content.description`、`location.*`、`salary.*`から表示を生成。同一会社情報を再入力させない | 募集主・雇用主・受付代行が異なる理由。会社マスタにない情報だけ確認 |
| 固定残業 | 金額、対象分、基本給、超過分支給から文章・不足を生成 | 対象が時間外／休日／深夜のどれか、複合制度。現行スキーマでは十分に区分できず要確認 |
| 最低賃金 | 保証下限・対象手当・所定時間・勤務地・有効日から比較 | 算定時間の根拠、特定最低賃金の適用、減額特例の許可。企業に「最低賃金を満たす時給」を二重入力させない |
| 試用期間 | 条件差分から「同条件」又は差分明示を生成し、別条件も再評価 | 延長条件、研修・見習いが試用とは別の場合の期間・条件。現行構造だけで複数の変更段階を表現できるとはしない |
| 年齢・深夜 | `age.*`、契約、勤務パターンの整合を検査 | 例外の実質的要件。時刻から深夜に該当するだけで全員を18歳以上に固定しない |
| 休日 | 曜日・周期・日数・勤務パターンの矛盾を検出 | 4週間カレンダーや交替制の実態。月4休だけから法定休日適合を認定しない |
| 手当・福利厚生 | 支給対象・保証・条件を既存構造から反映 | 費用負担・返還・選択条件等、応募判断に重要な欠落だけ確認 |
| 28日 | `publication.started_at/expires_at`から自動判定 | 再掲載時の募集継続・内容変更。企業へ期限日を再入力させない |

かんたん入力と詳細入力は同じルールを適用する。ステップ修正は該当フィールドのみ質問し、通常編集へ移動できる。企業・運営編集、複製、CSV取込、再掲載のすべてで対象版を再評価する。過去の「チェック済み」や許諾を無期限にコピーしない。編集で掲載開始を更新して期限を延長しない。

複数の職種・勤務地・給与・契約形態の対応が曖昧な原稿はerror。同条件の仕事内容説明まで細分化を強制しない。別条件の求人は無料複製から作成する案とし、紙媒体の同時募集欄・番号付けのルールは移植しない。

| W11 | L12 | ホワイト案件／即日即金／高収入／運ぶだけ／荷物受取 | warning、複数兆候なら運営確認 | 実際の犯罪・詐欺募集が確認された場合 | 合法な物流、専門職の高給与、通常の日払いもある。報酬、品物、依頼者、目的、雇用主を質問 |
| W12 | L12 | Signal／Telegram／消えるメッセージ／身分証をDM | 文脈判定＋運営確認 | 犯罪勧誘・個人情報を使った脅迫等が確認された場合 | アプリ名だけでなく唯一の応募先、実在情報の欠落、秘密指示との組合せを見る。通常の連絡手段も一律禁止しない |
| W13 | A04、B12 | 必ず稼げる／絶対採用／誰でも月収○万円／No.1／最高 | warning、具体的矛盾はerror | 故意の詐欺的誘引が確認された場合 | 「最低保証」「必ず超過分を支給」等の正当な保障を除外。対象・根拠・保証条件を確認 |

文字列正規化は全角半角・空白・大文字小文字などの候補を扱うが、元原稿を保存し検出箇所を示す。伏字・分割書き・画像にした表現は文字列照合で網羅できない。画像は現行スキーマの対象外であり、OCRや画像審査の実装を追加しない。危険語を言い換えれば掲載できる設計にしない。

商標名だけでは侵害が確定しない点は[特許庁の説明](https://www.jpo.go.jp/faq/yokuaru/trademark/shouhyou_seido_faq.html)を踏まえた判断。許諾が疑わしい広告利用は、0ENの第三者権利保護の方針として確認完了まで保留する案とする。

## 6. 0EN独自ルール候補（青本由来と分離）

以下は候補であり、不自然さの数値閾値・自動拒否条件は未確定。単一兆候でblockしない。組合せと追加確認で危険性が解消しなければ保留する。既に犯罪・詐欺・重大な権利侵害と確認された募集自体はblockの方針。

| ID | 対象・候補分類 | 判断理由・由来 | 自動判定と既存スキーマ | 質問／対応 | 要確認 |
|---|---|---|---|---|---|
| O01 | 求人者の実在・事業実態が確認できない：unable_to_evaluate | 法令関連通知＋安全。無料投稿のなりすましを防ぐ | `job.company_id`、`employer.*`は入力照合のみ。確認結果は企業管理側で未収録 | 公的情報等で企業単位に確認。既に確認した情報を求人ごとに再提出させない | 個人事業主・新設企業・名義変更・代理投稿、確認手段と更新周期 |
| O02 | 仕事内容に比べ報酬が不自然：warning→重大疑義はunable_to_evaluate | 安全、L12 | `salary.*`、`content.description`、`schedule.*`。通貨・単位・手当・時間を揃えられないと比較不能 | 金額の単位、具体業務、保証条件を質問 | 比較母集団・閾値・誤検出率。高い給与を抑える目的にしない |
| O03 | 仕事内容が極端に曖昧、詳細は応募後だけ：error／unable_to_evaluate | 明示＋安全 | `content.title/description`、`location.*`。必須不足は機械、実態は人 | 何を、誰の依頼で、どこで扱うか。営業秘密を理由に職務全体を隠さない | 説明の最小水準、一般名詞の検出条件 |
| O04 | 募集主と応募先・送金先の不整合：warning／unable_to_evaluate | 安全、なりすまし防止 | `employer.*`、`application.method/destination`。ドメイン違いだけで拒否不可 | ATSや正式代理業者の関係、委託範囲を確認 | 応募仕様未決定。フリーメール・無料ATS・グループ企業の例外 |
| O05 | 匿名アプリだけへ誘導し、企業確認前に身分証・家族連絡先を求める：unable_to_evaluate | 安全・個人情報保護 | `application.*`、`content.selection_info/description`。語検出は兆候 | 目的と正規連絡先を質問。不審点未解消なら保留 | 確認対象と証拠、緊急時の連絡先 |
| O06 | 内容を伏せて外部登録・教材購入・保証金送金へ誘導：unable_to_evaluate、詐欺確認でblock | 安全。副業名目の料金詐欺 | `application.destination`、`content.description/requirements/benefits` | 仕事と契約・費用・提供主体を確認。具体業務がない販売誘導は掲載対象外 | 合法な資格取得・機材費との区別、料金取得の主体 |
| O07 | 口座・携帯・名義の貸与、他人の現金受取等：unable_to_evaluate、犯罪募集確認でblock | 法令候補＋安全 | `content.description/requirements`。仕事内容の文脈が必要 | 名義・運搬物・顧客・用途を確認 | 正常な経理・配送・携帯販売業務を除外する基準 |
| O08 | 退職不能、罰金、脅し、身分証原本保管：unable_to_evaluate、違法・強制確認でblock | 労働者保護＋安全 | `content.requirements/selection_info/benefits`、`salary.note` | 拘束・返済・控除の条件を確認し適法な条件へ修正 | 違約金と実費返還の区別、強制の証拠 |
| O09 | 架空求人・終了求人・応募後の別案件強制：unable_to_evaluate、虚偽確認でblock | 的確表示＋安全 | `publication.*`、`history.*`、`content.*`。28日だけで実在判定不可 | 募集継続確認、通報・求人条件の照合 | 求職者アカウントなしでの通報受付、証拠・反論・復帰基準 |
| O10 | 停止求人を複製・CSV・再登録で復活：block候補 | 安全・運営統制 | `job.company_id/copied_from_id`、`publication.state`、`history.*`。同一主体の確実な照合のみ | 原因解消と運営解除を必要とする | 名寄せ・別企業との誤認防止、保存期間 |
| O11 | 大量の同一求人・更新で新着独占：warning／制限候補 | 鮮度と求職者の探索を保つ0EN独自基準 | `job.company_id`、内容版、`publication.started_at`。類似性だけで不正認定不可 | 本当に別勤務地・別条件か確認 | 上限や新着扱いは未確定。複数求人無料の方針を守る |
| O12 | 外部ページだけに条件を置き、本体の情報を省略：error | 明示＋安全 | `employer.*`、`content.description`、`location.*`、`salary.*` | 0EN本体に必要情報を表示。リンクは補足にする | L02の照会対応による例外を0ENで採用するか。初期案は採用しない |

「ブラック企業」というラベルや口コミだけで自動blockしない。具体的な未払賃金条件・危険作業・虚偽募集・差別・強制・反復違反等をルール化し、通報の真偽・当事者の説明を確認する。運営停止は証拠と理由を残す。定期点検、疑義が残る場合の拒否・保留、公開後の停止・記録保全は[L02](https://www.mhlw.go.jp/content/001423401.pdf)を踏まえた運用案であり、外部への通報を今回実行するものではない。

## 7. 重要な選別・緩和と注意

| 青本の基準 | 0EN案 |
|---|---|
| 他求人媒体の案内不可、指定メディアだけ紹介可、同号・別号・台割制限 | allow。公式企業ページ・合法な応募先・補足求人へのリンクを認める。ただし0EN側の必須明示を省略しない |
| 特定の欄に書く／番号付け／定型文だけ可／日本語のみ | 紙面都合の部分はallow。意味・条件対応が明確かを確認。日本語＋他言語の説明を禁止しない |
| 主婦・外国人・女性活躍・明るい等の語を厳格に制限 | 事実説明・包摂的呼びかけ・職務上の行動期待はallow候補。性別優遇・家庭属性等による排除は別途error／要確認。単語だけの緩和ではない |
| 年齢不問＝15歳以上、古い氷河期施策期限 | その数値・期限を移植しない。児童就労の基準と法令例外を最新資料で確認 |
| 国籍不問等が不可、留学生の古い校種別時間 | 国籍で排除しない説明はallow。就労資格の範囲は入管庁情報で別判断 |
| 給与の「税込み」不可／一律手当を待遇で再掲不可 | grossの意味が明確なら表現制限不要。手当は同じデータから表示し、二重加算・非保証額の混入だけ修正 |
| 現金特典一律不可／先着特典不可 | 支給主体・目的・規制を確認。雇用主の給与・入社手当と0EN・紹介業者の誘引を分ける。自動allowへも一律blockへも振らない |
| 研修無給や費用を省略できる例外 | 0ENでは労働性、重要費用・控除・返還条件を厳しく確認。青本で許容される省略でも求職者判断に必要なら明示させる |
| 新卒なら「総合職」だけ、給与未定でも前年額のみ | 0ENでは具体業務と確定／未確定を区別。前年実績を保証下限として検索させない。未確定条件の受付は要確認 |
| 複雑な派遣・紹介・委託・FCを媒体別に受付 | 業態の合法性とPoC対応範囲を分離。現行スキーマで明示・評価できない形態を黙って公開しない。受付範囲を先に決める |

公正採用の行政上の注意と個別の法違反を区別する。例えば「明るく挨拶できる」は職務上の行動説明として扱えるが、本人の出自・信仰・家庭環境の収集や排除は0ENの人権保護基準として認めない案。[L07](https://kouseisaiyou.mhlw.go.jp/consider.html)

## 9. 設計上の確認例

| 例 | 期待する判断 |
|---|---|
| 月給が高い専門職、仕事内容・保証額が明確 | 高給だけでblockしない |
| 仕事内容なし、「運ぶだけ」、高額即金、匿名アプリだけ | 必須不足はerror、複合重大疑義は判定不能で保留。犯罪確定でblock |
| 実際のディズニー関連企業の正式名が求人にある | 一致だけでblockしない。本人・権限・用途を確認 |
| 無関係な企業がオリンピック公式スポンサーを名乗る | 関係を確認。虚偽・無権限の広告利用が確定ならblock |
| 固定残業代の額・時間・基本給・超過分の記載不足 | error。登録済み項目から必要表示を生成して補う |
| 条件が同じ試用期間 | 同条件を派生表示。給与を二度入力させない |
| 「女性スタッフが在籍」、性別不問で同条件 | 事実説明としてallow候補。「女性のみ採用」と区別 |
| 別企業ドメインの正規ATSへ応募 | ドメイン違いのみで拒否しない。委託・応募先を確認 |
| 有期契約の年齢制限が「定年のため」だけ | 契約との矛盾はerror、例外の適用未確認なら判定不能 |
| 停止中求人を複製・CSV更新・運営編集 | 停止理由を迂回して自動復帰させない |

本書と棚卸し以外のリポジトリファイル、Vault資料、求人共通スキーマは変更しない。D1・フォーム・API・DB・ルールエンジン・危険語辞書の実装は行わない。
